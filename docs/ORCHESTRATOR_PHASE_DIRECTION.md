# Orchestrator Phase Direction

## Why this document exists

The project is now complete through Task 175.

That means the one-task lane has already reached a conservative supervised readiness checkpoint, and the bounded supervised two-task pilot has also reached a conservative preparation-and-re-proof checkpoint.

The honest next move is therefore not broad autonomy. It is bounded pilot operation with real curated pair evidence.

## Agreed phase order

### Phase A — Keep one-task execution truthful and stable

This remains the base layer.

The one-task lane is conditionally ready under supervision, and its scorecard and promotion truth remain the authoritative gate for any future widening.

### Phase B — Operate the bounded supervised two-task pilot conservatively

This is the current active phase.

The goal is not arbitrary multi-task execution. The goal is to exercise the smallest credible adjacent two-task pilot with:

- mechanical pilot admission,
- deterministic adjacent-task handoff,
- explicit supervised dev/test role separation,
- durable pair-level ledgers,
- explicit supervised-intervention truth,
- and real corpus-backed benchmark evidence.

This phase is represented by Tasks 176–180.

### Phase C — Consider cautious widening only after durable two-task corpus proof

This comes only after the bounded pilot has been exercised over a curated adjacent-pair corpus and the resulting evidence is durable enough to justify a conservative next step.

Even here, the likely next move is still supervised and bounded widening, not broad unattended autonomy.

### Phase D — Productize the orchestrator as its own app

This phase still comes later.

The orchestrator should only be wrapped in a separate operator-facing product after stronger multi-task proof exists. Building an app shell around a still-bounded pilot would still be premature.

## What this means right now

Optimize the current tranche for:

1. an exact two-task pilot runner
2. a curated adjacent-pair corpus and manifest
3. durable pair-level ledgers and intervention truth
4. a real corpus benchmark over bounded pilot pairs
5. a conservative widening checkpoint that still blocks broad autonomy and standalone product claims unless the evidence clearly supports a later step

## What remains blocked

The following remain explicitly blocked in the current phase:

- broad unattended multi-task autonomy
- arbitrary-length manifest scheduling
- general multi-agent role orchestration across arbitrary work
- standalone orchestrator-as-its-own-app productization
